# Browser Extensions: independent versions and build/release ownership

**Code and packaging acceptance scope, 2026-10-10.** Actual installed
Tampermonkey/Chromium operation, real-account source backups, extension-ID
cutover and publication remain separately gated acceptance levels.

## Current version matrix

| Product | Version | Entry point | Tampermonkey | MV3 | Publication |
| --- | --- | --- | --- | --- | --- |
| VK Booster | 2.3.8 | `modules/vk-booster` | Separate VK only | Separate VK only | Independently tagged |
| ChatGPT Booster | 2.0.1 | `modules/chatgpt-booster` | Separate ChatGPT only | Separate ChatGPT observer, worker, popup | Independently tagged, manual approval |
| All-in-one | 0.5.0 | `apps/userscript/src/all-in-one.ts`, `apps/extension/src/all-in-one-content.ts` | VK and ChatGPT by site | VK plus ChatGPT observer and worker | Own tag/channel, manual approval |

`apps/all-in-one.json` declares dependencies on VK and ChatGPT. Its one
Control Center and feature registry select the corresponding provider on the
current host; no provider source data is silently uploaded or copied between
sites. The plain VK target retains the exact preexisting `content.ts` and
`popup.ts` entry behavior. ChatGPT standalone and all-in-one reuse the same
factory composition per target. No duplicated provider archive engine is
compiled for different distribution targets.

## Version-change graph

| Changed implementation | Required version change | Must remain unchanged |
| --- | --- | --- |
| `modules/chatgpt-booster/**` | ChatGPT and all-in-one | VK |
| `modules/vk-booster/**` | VK and all-in-one | ChatGPT |
| `apps/all-in-one*` | All-in-one | Both standalone products |
| Shared `packages/**` | VK, ChatGPT and all-in-one | Disabled proxy target |
| Documentation-only or CI-only | None | All product versions |

Run `bun scripts/bump-versions.ts <changed implementation path>...` to plan
and write product manifest **patch** bumps, including private product
package metadata, the runtime version identifier and the Bun lockfile. Larger semver updates should be
chosen deliberately; the first ChatGPT version-2 release is `2.0.1` and the
aggregator feature release is `0.5.0`. PR CI executes
`scripts/version-policy.ts` against the pull-request base SHA and refuses
missing or unrelated product version increments.

A successful build produces three separate userscripts and Chromium ZIPs.
`bun scripts/validate.ts --built` verifies their versions, independently
scoped updates, embedded module identifiers, MV3 script/world/host constraints
and permission isolation.

## Release operation and safety

Releases are generated by one manual-only workflow on `main` with mandatory
`approve_release=true` and dependency-aware `release_scope`:

- `chatgpt-booster`: only ChatGPT and all-in-one eligible;
- `vk-booster`: only VK and all-in-one eligible;
- `all-in-one`: only aggregator eligible;
- `all`/`shared`: all releasable modules eligible.

Module-scoped tags (`chatgpt-booster/v2.0.1`, `vk-booster/v2.3.8`, etc.)
and stable Tampermonkey distribution branch paths prevent a release of one
module from changing another module's update channel. The workflow never
runs automatically from a source integration merge. A clean CI build is
**not** production acceptance of an installed extension or a statement that
old user data has been migrated.

## Decomposition review against VK

The VK runtime separates its source API, media mapping, state/selection,
offline viewer and Archive Manager presentation, and consumes shared
`packages/archive`, `packages/storage`, `packages/widgets`, `packages/ui` and
`packages/shell` surfaces. ChatGPT has separate provider packages for
`core`, `chatgpt`, `observer`, `telemetry`, `features`, `ui`, `userscript`
and `extension` and uses the same shared runtime, shell and archive helpers.
Standalone and all-in-one are now thin composition/delivery entries.

ChatGPT's `archive-v4-store.ts` and `archive-canonical-migrator.ts` remain
large provider-owned implementations, respectively roughly 2200 and 1900
source lines. They are **not** mechanically replaced by VK's linear
checkpoint engine: ChatGPT's native branch graphs, verified account identity,
source fingerprints, v3/v4 IndexedDB and canonical recovery invariants are
different. The `integrations/chatgpt-booster/` historical decomposition is a
non-distributed reference, not a second shipped module. The remaining
provider-specific decomposition and installed-browser acceptance should be
tracked separately rather than weakening these storage contracts for a
release shortcut.
